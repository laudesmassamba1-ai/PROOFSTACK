# PROOFCORE — matrice des capacités

État mesuré le 25 novembre 2026. Chaque « oui » renvoie à un test ou à un parcours
exécuté dans cette passe. Une capacité sans preuve est marquée **PARTIEL**,
**ABSENT** ou **NON VÉRIFIÉ** — jamais disponible.

Vocabulaire :

- **VÉRIFIÉ** : code + test exécuté et passé + parcours réel.
- **PARTIEL** : fonctionne, avec une limite nommée.
- **ABSENT** : non implémenté, non présenté comme disponible.
- **NON VÉRIFIÉ** : code présent, preuve externe impossible sans credentials.

## 2. Limites précises des chemins d'exécution

- Le parcours Start/Scan utilise `POST /api/v1/audits` et enregistre un `PageAudit` dans
  l'historique des scans. Ce n'est pas le même objet qu'un `EngineRun`.
- Les outils IA `module_run` pour FAIL/CLEAN appellent le scanner HTTP et enregistrent
  un `PageAudit` dans l'historique des scans. Ce chemin ne crée pas d'`EngineRun` ni de
  `RunReport` : `auditId` identifie l'audit de page, tandis que `runId` et `reportId`
  restent nuls par conception. `module_status` expose le dernier audit et `get_report`
  peut relire son contenu via `auditId`.
- WORLD et les scénarios FLOW compatibles avec le moteur serveur créent un run persistant
  et soumis au quota de runs. Les journeys Chromium restent locaux à la CLI.
- EXIT reste local dans le Worker lorsque sa source nécessite un fichier ou une commande.
  Même une source HTTP ne doit pas être déclarée exécutée côté Worker tant que le code ne
  fournit pas un chemin d'exécution et une preuve correspondants.
- Un résultat d'outil est persisté uniquement lorsque son contrat le prévoit. `module_run`
  persiste les EngineRun WORLD/FLOW compatibles et les audits FAIL/CLEAN comme PageAudit.
  Les réponses textuelles de l'assistant et les autres outils de lecture ne créent pas
  automatiquement un élément d'historique.

## 3. Ce qui n'est pas une capacité

Un dossier, une route ou un onglet ne prouve rien. Ne sont pas comptés comme
fonctionnalités : les pages marketing des modules, les entitlements déclarés sans
implémentation, les écrans qui affichent un état vide, et les webhooks seulement
enregistrés sans livraison observée.
